# Shirakami Conformance — Draft

## Purpose

This document defines the intended separation between implementing Shirakami technology and claiming Shirakami conformance.

## Conformance is a claim about observable requirements

An implementation may be technically different from the reference implementation and still be conformant if it satisfies the applicable normative protocol requirements.

Conformance should therefore be tested against observable contracts rather than source-code similarity.

## Initial normative areas

The conformance framework is expected to cover, where applicable:

1. Human Gate preservation.
2. Authority non-propagation.
3. Evidence identity and provenance preservation.
4. Semantic Handoff integrity.
5. AIwitness boundary integrity.
6. Traceability closure.
7. Reviewer-perspective preservation for comparative review.
8. Separation of observation from decision authority.

## Certification status

A test passing in the repository is evidence about that test. It is not by itself a certification of an external product or proof of the entire Shirakami model.

## Branding

Final rules for use of the Shirakami name, logo, certification badges, or phrases such as Shirakami-conformant should be defined separately from copyright licensing and reviewed as a trademark/branding matter.

## Versioning

Conformance requirements should be versioned with explicit compatibility rules so that vendors can identify which protocol and conformance version they implement.

## Draft status

This document is a design artifact and is not a legal certification policy.
