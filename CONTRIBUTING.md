Shirakami OS is an architecture-first project. Contributions should preserve the architectural integrity before introducing implementation changes.

# Purpose

Shirakami OS is developed through an RFC-first architecture: design and architectural proposals are captured as RFC documents, reviewed, and accepted before implementation begins.

# Development Principles

- Foundation First
- Architecture Before Implementation
- One RFC, One Concept
- One Commit, One Purpose
- Documentation Before Code

# Contribution Workflow

RFC

↓

Review

↓

Accepted

↓

Implementation

↓

# Commit Guidelines

Make small, focused commits that address a single purpose. Prefer clear commit messages describing the intent and scope of the change.

# Pull Request Guidelines

- Reference related RFCs in the PR description.
- Explain the architectural intent and why the change is needed.
- Link design discussions or issues when relevant.

# Code of Conduct

Treat contributors with respect. Focus discussion on ideas and architectural trade-offs, not on individuals.

Architecture is our shared language.
