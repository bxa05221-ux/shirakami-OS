# R0013 — Evidence Lineage Across Multiple Transitions

## Purpose

Observe whether multiple Runtime transitions can be preserved as an ordered Evidence lineage without Runtime inferring semantic continuity.

## Scope

This experiment uses the existing Runtime → Evidence → Landscape path with multiple transitions. It does not add a continuity detector, migration logic, replay semantics, or new Kernel/Evidence schema.

## Fixture

```yaml
landscape:
  state_id: "landscape-r0013-001"

transitions:
  - transition_id: "transition-r0013-001"
    protocol_id: "r0013.lineage.v1"
    kind: "r0013.landscape.transition"
    changed: true
    source_landscape_state: "landscape-r0013-001"
    resulting_landscape_state: "landscape-r0013-002"

  - transition_id: "transition-r0013-002"
    protocol_id: "r0013.lineage.v2"
    kind: "r0013.landscape.transition"
    changed: true
    source_landscape_state: "landscape-r0013-002"
    resulting_landscape_state: "landscape-r0013-003"

  - transition_id: "transition-r0013-003"
    protocol_id: "r0013.lineage.v3"
    kind: "r0013.landscape.transition"
    changed: true
    source_landscape_state: "landscape-r0013-003"
    resulting_landscape_state: "landscape-r0013-004"
```

## Observation Question

Can multiple transitions be represented by multiple Evidence records while preserving their order and protocol/transition identity, without producing a semantic continuity claim?

## Expected Boundary

Expected observable result:

- Evidence records retain protocol identity and transition identity.
- Evidence order can be inspected from the accumulated records.
- Landscape projection can accumulate the observed changes.
- No `continuity`, `continuity_claim`, or semantic interpretation is generated by Runtime.

## Non-goals

- continuity scoring
- semantic continuity detection
- migration
- replay semantics
- new Kernel/Evidence schema
- domain interpretation
