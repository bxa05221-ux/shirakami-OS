# How Shirakami OS Happened

## A developer story

> **A former pastor, nursery school director, prison chaplain, and now the owner of a disability employment support organization in rural Japan.**
>
> **At 56, he started using AI in June 2025 to write a novel.**
>
> **Somehow, he ended up creating the Shirakami Model, a meta-protocol for generating protocols.**
>
> **Then he got carried away, connected it to GitHub, and is now building an OS.**

This is not a conventional AI research biography.

The point is not that the developer started as an AI engineer. He did not.

The point is how a conversation with AI gradually became a development environment.

## From writing to protocol engineering

The starting point was creative work: using AI to write a novel.

During that process, a different problem became visible: how should an AI preserve context, perspective, conversational state, and human intent instead of treating every exchange as an isolated prompt?

Protocols became a way to make those relationships explicit.

The Shirakami Model emerged as a cognitive observation framework, and Matome YAML became the formal handoff format used to express protocols for the runtime.

## From protocol to GitHub

The next step was not simply to store code in GitHub.

GitHub became part of the development loop:

```text
Human question
      ↓
AI dialogue
      ↓
Protocol / Matome YAML
      ↓
Implementation
      ↓
GitHub
      ↓
Tests / PRs / Commits
      ↓
Evidence
      ↓
Architecture revision
      ↓
AI dialogue
```

The repository became an external development landscape: a place where specifications, experiments, implementation, tests, review, and history could remain visible and connected.

## The unusual part

The developer did not begin with a plan to build an operating system for AI.

The architecture emerged through repeated cycles of questioning, implementation, observation, criticism, and revision.

External AI systems are used as reviewers and development participants, but their suggestions are not treated as truth. They become observations that can be tested.

This distinction is important:

> **AI does not own the architecture. Evidence does.**

## Why this story matters

Shirakami OS is an experiment in a different way of building AI infrastructure.

The central question is not:

> How do we build a more capable AI model?

It is:

> **How can a human keep their Landscape when the AI changes?**

The development process itself is part of the experiment.

Human experience, AI dialogue, protocols, repositories, tests, and evidence are treated as connected parts of one evolving Landscape.

## Today

The project has grown from a creative-writing experiment into an open-source exploration of:

- Human Landscape preservation
- Protocol-driven AI behavior
- Personal AI Runtime architecture
- Evidence-driven development
- Runtime boundaries
- Model-agnostic context continuity
- AI-assisted repository development

The story is still being written.
