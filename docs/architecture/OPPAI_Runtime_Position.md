# OPPAI Runtime Position

Status: architecture feedback

OPPAI is positioned at the human-facing input boundary of Shirakami OS.

```text
Human Landscape
      ↓
Natural Interaction
      ↓
OPPAI Schema
      ↓
Protocol Selection / Context Handling
      ↓
Runtime
      ↓
AI Adapter
      ↓
Observable Result
      ↓
Evidence / Landscape Change
```

## Boundary rule

OPPAI may organize what is explicitly observable in the interaction, but must not silently manufacture hidden intent, factual certainty, or psychological diagnosis.

## Operational principle

The user should not have to operate OPPAI. OPPAI should operate as infrastructure beneath ordinary interaction.

The target state is not protocol awareness by the user, but reduced human adaptation to machine-oriented input requirements.

## Relationship to existing layers

- Anmon Layer: preserves unresolved questions and prevents premature closure.
- Phase Rotation: supports movement across perspectives without forcing one interpretation.
- Thread RPG: permits distributed observation and interaction.
- Evidence Contract: keeps observation separate from interpretation and decision.
- Permission: remains authoritative for what may be retained or exposed.

## Non-claim

This document does not establish that OPPAI improves any benchmark or downstream model capability. It defines an architectural position to be tested through implementation.
